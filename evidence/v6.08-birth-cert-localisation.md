# v6.08 — 出生登記證明只有中英兩種語言

## 量到的缺陷

出生登記卡是**每個玩家看到的第一個畫面**。`buildBirthCertCard()` 是一個
53 行的函式，裡面有 **22 個硬編碼的中英三元運算式**：

```js
${isEn ? 'OFFICIAL BIRTH REGISTRATION' : '出 生 登 記 證 明'}
${isEn ? "Father's age / job" : '父親年齡／工作'}
${isEn ? 'Under-5 mortality' : '5 歲前死亡機率'}
...
```

而 `data/i18n.json` 裡**早就存在 21 個翻譯完整的 `intro.bc.*` key，九種語言都有**，
只是完全沒被任何程式碼引用。

（模組的三顆按鈕「取消 / 換一個國家 / 開始這段人生」有掛 `data-t`，
所以只有卡片本體卡在兩種語言。）

實測修前的輸出（切到日語）：

```
出 生 届 出 証 明 ... 出 生国 ... 世帯所得 ... 父の年齢/職業
```

英文以外的七種語言看到的就是繁體中文。

## 修法

1. 補上唯一缺掉的 6 個 key（父母住的房屋類型），九種語言各一份：

   `intro.bc.housing.farm` / `.village` / `.suburban` / `.modern` / `.block` / `.slum`

   | 語言 | farm | slum |
   |---|---|---|
   | zh-Hant | 農舍 | 貧民窟／非正式住宅 |
   | en | Farm | Slum / informal settlement |
   | ko | 농가 | 빈민가 / 비정규 정착지 |
   | ja | 農家 | スラム / 非正規住民区 |
   | th | ไร่ | ชุมชนแออัด / ถิ่นอยู่อาศัยไม่เป็นทางการ |

2. 整張卡片改走 `t('intro.bc.*')`（20 個位置）
3. 順帶把內聯的「yrs / 歲」換成既有的 `unit.years` key，並移除因此不再用到的 `isEn`

## 修之後（印度人生，五種語言實測）

```
zh-Hant: 出 生 登 記 證 明 … 父親年齡／工作 … 父母住房 貧民窟／非正式住宅 宗教 印度教
en     : OFFICIAL BIRTH REGISTRATION … Father's age / job … Parents' housing …
ko     : 공 식 출 생 등 록 … 아버지 연령 / 직업 …
ja     : 出 生 届 出 証 明 … 父の年齢/職業 …
th     : ท ะ เ บี ย น ก า ร เ กิ ด … อายุ …
```

六個新 key 的取值也逐一驗過：

```
zh-Hant 農舍 / 貧民窟／非正式住宅
en      Farm / Slum / informal settlement
ko      농가 / 빈민가 / 비정규 정착지
ja      農家 / スラム / 非正規住民区
th      ไร่ / ชุมชนแออัด / ถิ่นอยู่อาศัยไม่เป็นทางการ
```

`i18n_audit.py` 的「referenced keys」從 **535 增加到 559**。

## 這個修法差點騙過我，值得記下來

稽核腳本回報 **「559 referenced keys all resolve」** —— 全部通過，看起來沒問題。

但實際執行 `t('intro.bc.housing.farm')` **回傳的是 key 字串本身**，不是翻譯。

比對之後找到原因：

```
page 記憶體裡的 I18N：726 個 key（舊版）
network 的 i18n.json：732 個 key（新版，有 housing.farm = 農舍）
service worker 的 cache：已有新版
```

**頁面是在新的 Service Worker 完成預存之前就把 i18n.json 讀進記憶體的。**
所以「清掉 SW 和 cache 再重載」還不夠 —— 舊的那一份已經在記憶體裡了，
要**再重載一次**才會拿到新的。

這是 v5.94 修好「SW 預存舊檔」之後仍會遇到的下一層問題：
預存本身正確了，但頁面自己 `fetch()` 的時機可能早於預存完成。

量測方式：以後加完 key 之後，除了清 cache，**要在新的 SW 安裝完成之後再多重載一次**，
並且用「記憶體 vs 帶 cache-busting 的 fetch」兩邊對照來確認，不要只看畫面。

## 這個缺陷怎麼找到的

和 v6.06（自殺率）、v6.07（宗教）是同一個家族的最後一塊拼圖：
**把資料檔的欄位／key 逐一對照程式碼裡的引用**。

```
$ 把 countries.json 的欄位對照 app.js     → 發現 sf（v6.06）、rel（v6.07）
$ 把 i18n.json 的 key 對照 app.js/html   → 發現 intro.bc.*（這次）
```

兩個檢查都是幾秒鐘的成本，抓到的都是量級不小、而且**看起來完全正常**的錯誤。

## 已知限制

- 這個專案還有其他硬編碼中英雙語的內容（年齡層事件池 `generateYearlyEvent`、
  狀態說明面板、`REL_ZH`/`REL_EN` 字母表等），在非中英文語言下仍是中文或英文。
  那些是**內容撰寫**問題（要補 key 並翻譯），不是接線錯誤，所以沒有混在這次修。
- `t()` 在 key 找不到時會原樣回傳 key 字串，不會報錯也不會在 console 留下線索。
  這一點讓「key 沒接上」和「key 沒定義」在外觀上完全一樣 ——
  把 `t()` 改成缺值時拋出警告，應該能讓這類問題以後自己浮出來。
