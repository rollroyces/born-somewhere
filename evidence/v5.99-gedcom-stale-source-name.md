# v5.99 — 匯出的 .ged 檔案裡寫著這個專案改名前的舊名

## 量到的缺陷

匯出一份族譜 GEDCOM，把檔案內容讀出來，檔頭是：

```
0 HEAD
1 SOUR zu-pu          ← 舊專案名
1 GEDC
2 VERS 5.5.1
2 FORM LINEAGE-LINKED
1 CHAR UTF-8
1 NOTE 族譜 · 林家銘
```

本專案現在叫 **born-somewhere**（網域 `born-somewhere.app`、localStorage key
`born-somewhere-v2`、匯出檔名 `born-somewhere-<name>-<ts>.json`）。
`zu-pu` 是改名前的名字。

`SOUR`（SOURCE）是 GEDCOM 裡會被族譜軟體當成「來源」顯示的欄位，
所以每一份玩家匯出的 .ged 都掛著一個不存在的專案名。

## 修法

```js
ln(0, 'HEAD');
ln(1, 'SOUR', 'born-somewhere');
```

## 順帶驗證：GEDCOM 往返

因為使用者會匯出再匯入，所以做了一次完整的往返測試：

```
匯出 → 8 個 INDI / 4 個 FAM，檔頭 HEAD + 檔尾 TRLR
匯入 → window.Gedcom.import() 無錯誤，8 個人，parent 連結正確
       self 正確辨識（p1 林家銘, parents: [p2, p3]）
再匯出 → 8 個 INDI，與第一次完全一致（roundTripStable: true）
```

結構也符合 GEDCOM 5.5.1：`0 HEAD` / `1 SOUR` / `1 GEDC` / `2 VERS 5.5.1` /
`2 FORM LINEAGE-LINKED` / `1 CHAR UTF-8`，個體有 `NAME` / `SEX` / `BIRT` / `DEAT` /
`PLAC` / `FAMC` / `FAMS`，家庭記錄 4 組。

## 已知限制

- 沒有實測其他族譜軟體（Gramps / FamilyEcho 等）實際開啟這個檔案的相容性。
  結構符合 5.5.1，但真實軟體常有各自的寬容度差異，要確認得真的匯入一次。
- 匯出的 `1 NAME` 同時帶了本地姓名與英文名（`雅琪 /彭/` 與 `Gonzalez Hua` 兩行），
  這是刻意的（讓軟體裡看得到兩種名字），但部分軟體只會取第一行。
- 樹狀圖在 360px 寬時節點文字偏小，看不清楚。實測樹狀圖本身有正常渲染
  （self → 父母 → 祖父母，含連結線），這是版面密度問題不是功能缺陷，
  與本專案在 ≤520px 刻意收起次要控制鈕是同一種取捨，本次不動。
