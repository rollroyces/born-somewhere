# v5.92 — 15 歲寫下的一句話，被存成 19 歲

## 量到的缺陷

在 age 1 的某一刻，畫面上同時開著兩個視窗：

```
pauseModal     「如果 15 歲的你能記得一件事⋯」     ← 反思題
decisionModal  「這個週末怎麼過？」                 ← sm_weekend 決策
STATE.pendingDecision = { kind:'decision', id:'sm_weekend', age:19, _dismissed:true }
```

玩家照著「15 歲」那道題目打完字、按儲存，得到的是：

```js
life.quotes = { "19": "想當一個讓人放心的大人" }
getLifeStory(life) === "【19歲】想當一個讓人放心的大人"
```

**問的是 15 歲，存的是 19 歲。** 而且 `pendingDecision` 只有一個槽位，
`showDecision()` 和反思題共用它（`app.js:92` 寫入、`savePauseQuote()` 讀取），
任何決策插進來都會把反思題的年齡蓋掉。

## 為什麼玩家真的會遇到

`showPauseQuestion()`（v5.33）刻意**不再**設 `STATE.paused = true`，
註解明寫「讓生命繼續在背景跑；modal 顯示但可手動互動」。所以反思視窗可以
一直開著 —— 實測有從 5 歲一路開到 33 歲的案例，中間跨過多個決策年。

`tryTriggerDecision()` 的防疊層只檢查自己：

```js
const decM = document.getElementById('decisionModal');
if (decM && !decM.hasAttribute('hidden')) return false;
```

v5.84 修過 `pause + finance` 疊在一起，但 `decision + pause` 這條漏了 ——
因為防疊層從來沒有檢查 `pauseModal`。

## 修法（兩個分開的問題）

### 1. 反思題的年齡不再跟 `pendingDecision` 共用

```js
// showPauseQuestion()
STATE.pauseQuestionAge = age;

// savePauseQuote()
const age = STATE.pauseQuestionAge ?? STATE.pendingDecision?.age;   // pendingDecision 只當舊存檔退路
```

### 2. 決策不再疊在反思視窗上 —— 選「讓位」而不是「擋住」

```js
// showDecision() 開啟前
const pauseEl = document.getElementById('pauseModal');
if (pauseEl && !pauseEl.hasAttribute('hidden')) closeModal('pauseModal');
```

這裡刻意**不**改成「反思視窗開著就不觸發決策」。那樣做比較直覺，但會讓
反思視窗（可能開著好幾十年）擋掉整段人生的所有決策，直接把 v5.85 建立的
23/24 決策可達性打下來。改成讓位之後，決策照常出現，只是反思視窗先收掉。

## 修之後

決定性測試（先開 15 歲反思題，再讓決策佔用 `pendingDecision`，最後按儲存）：

| | 修之前 | 修之後 |
|---|---|---|
| 存入的年齡 | **19** | **15** |
| 人生故事 | `【19歲】…` | `【15歲】…` |
| 決策開啟後反思視窗 | 仍開著（兩個疊在一起） | **已關閉** |

## 已知限制

- 反思視窗仍然不會暫停人生（v5.33 的既定設計）。玩家如果真的放著不管，
  它會一直開到玩家按掉為止；決策會把它蓋掉收走，但視窗本身不會自動消失。
- `STATE.pauseQuestionAge` 沒有在 `closeModal('pauseModal')` 時清掉。
  留著是刻意的：舊存檔（沒有這個欄位的人生）仍能靠 `pendingDecision` 撐住，
  而新存檔不會因為多按一次儲存而改變年齡。
- 這個 bug 只在玩家**主動打字**時才會被看見。多數玩家會按「略過」，
  所以這個缺陷在實務上不會天天發生 —— 但它壞掉的是這個遊戲最情感核心的
  功能（替某個年齡的自己留一句話），值得修。
