# v5.89 — 老年事件不再輪流：加上重播冷卻並補上被掏空的年齡層

## 為什麼做這個

v5.88 的全人口校準把經濟數字結案了，但回頭看「玩起來的感覺」時，最刺眼的一點不是數字，是
**同一句話在 feed 裡反覆出現**。

實測 60 條人生（10 個國家各 6 條，跑到自然死亡）後，feed 的最後 20 年是這樣的：

```
80 歲 👨‍👩‍👧 孫子女來訪
81 歲 👨‍👩‍👧 孫子女來訪
82 歲 🌳 公園散步
82 歲 👨‍👩‍👧 孫子女來訪
83 歲 🌳 公園散步
85 歲 👨‍👩‍👧 孫子女來訪
```

老年二十幾年，玩家看的就是那 3 句在輪流。這正是「玩起來不好」的來源 ——
不是選項沒有意義（那是 v5.86／v5.87 解決的），而是**旁白本身沒有新東西可講**。

## 量到的缺陷（60 條人生）

| 指標 | 修之前 |
|---|---|
| 最後 20 年 feed 中「看過的舊句」占比 | **45.0%**（1349 筆中重複 835 筆） |
| 同一句在 4 年內再出現的次數 | **376 次**（全部相鄰重複，沒有一例拉開到 5 年以上） |
| 單句「公園散步」最高出現次數 | 60 條人生合計 100 次 |

根因在 `generateYearlyEvent()` 的事件池太小：

- `age >= 65` 這一層只有 **5 條**，其中 4 條標了 `rep: true`
- v5.62 已經處理「一生只該發生一次」的事件（`seenOnce`），但 **`rep: true` 完全沒有任何間隔限制**
- 一條 85 歲的人生要在 5 條裡抽 20 次 → 數學上必然反覆

換句話說，v5.62 修好了「同一生結五次婚」，但沒修「公園散步年年有」。

## 修法

兩件事一起做，缺一不可：

### 1. `REP_COOLDOWN = 6` 年的重播冷卻

`rep: true` 從「可以重複」改成「可以重複，但上一次之後要隔 6 年」。

用 `life.repSeen` 記錄每條 `rep` 事件上次發生的年齡（陣列不用 `Set`，因為
`lifeExport` 會把整段人生 `JSON.stringify`，`Set` 會變成 `{}`，與既有的
`seenOnce`／`seenWar` 同一個考量）：

```js
const repSeen = life.repSeen || (life.repSeen = []);
const lastRep = {};
for (const r of repSeen) lastRep[r.en] = r.age;
const pool = events.filter(e => {
  if (!e.rep) return !seen.includes(e.en);
  const last = lastRep[e.en];
  return last === undefined || (age - last) >= REP_COOLDOWN;
});
```

冷卻記在 `e.en`（英文）而不是顯示文字，所以切換語言不會讓冷卻失效。

### 2. 把被掏空的年齡層補滿

冷卻只是不讓它馬上重複；池子不夠大還是會繞回來。補到「池子大小 ≈ 該年齡層年數 ÷ 2」：

| 年齡層 | 修之前 | 修之後 |
|---|---|---|
| `< 5` | 4 | 8 |
| `< 13` | 5 | 10 |
| `< 18` | 5 | 10 |
| `< 30` | 6 | 10 |
| `< 50` | 7 | 13 |
| `< 65` | 6 | 13 |
| `>= 65` | **5** | **15** |

共新增 40 組事件（繁中＋英文），沿用這個函式既有的 inline `en`／`zh` 寫法，
不進 `data/i18n.json`，所以 `i18n_audit.py` 的基準沒有變動。

## 修之後（同一組 60 條人生，同一個量測腳本）

| 指標 | 修之前 | 修之後 |
|---|---|---|
| 最後 20 年 feed 不重複占比 | 45.0% | **77.6%** |
| 4 年內重複次數 | 376 | **0** |
| 最後 20 年重複筆數 | 835 | 519（−38%） |
| 全人生重複筆數 | 1199 | 1044 |

同一條人生（91 歲）的修後尾段：

```
74 🌳 公園散步 … 79 👨‍👩‍👧 孫子女來訪 … 81 🌳 公園散步 … 86 🪑 坐在長椅上看街景
87 🍵 和老友喝下午茶  88 🧶 學會了織毛衣  89 🕊️ 參加了一場喪禮  90 👨‍👩‍👧 孫子女來訪
```

重複都拉開到 7～9 年，玩家的記憶已經淡了。

## 順帶確認：沒有拿「重複」換成「冷清」

冷卻有可能把池子抽空、換成年年無事件的白色畫面。實測 5016 個年：

| | 修之前 | 修之後 |
|---|---|---|
| 沒有任何新事件的年份 | ~14% | **5.5%** |

反而**下降**了，因為池子變大、可抽的東西變多。分齡看也健康 —— 安靜的年份集中在
一次性事件用完的十年（0–9 歲 17.1%、70–79 歲 8.8%），20/40/60/80 幾個十年是 0%。
「那年沒什麼事發生」本來就比「同一句再講一次」好。

## 這次**沒有**做的事

一開始還想順手把保底事件的 `kind` 從 `'milestone'` 改成 `'flavour'`（因為
74% 的事件都被標成里程碑，稀釋了真正的里程碑）。讀完消費端之後確認**不會有任何
可見變化**，因此沒有做：

- `styles.css` 沒有 `.lef-row.kind-milestone` 規則 → 外觀完全不變
- `app.js:6115` 的「生命里程碑」面板篩選條件是 `kind !== 'log'` → 改字串也不會讓它消失

沒有使用者看得見的收益，就不該為它承擔改動風險。保留下來真的有人看的地方
（真正的 `event.school`／`event.marriage`／`event.retirement`）維持原樣。

## 驗證方式

```js
// 60 條人生、跑到自然死亡，最後比對 life.log 的文字重複度
for (let L = 0; L < 60; L++) {
  startLife(CC[L % CC.length]);
  for (let i = 0; i < 130 && !STATE.life.died; i++) {
    STATE.paused = false; tick();
    tryTriggerDecision(STATE.life, STATE.life.age);
    // 關掉 decisionModal / pauseModal / focusModal / financeModal / spendModal
  }
}
```

重複率 = `life.log` 中文字已出現過的筆數 ÷ 總筆數；「4 年內重複」= 相鄰兩筆
同文字且年齡差 ≤ 4。

### 已知限制

- 冷卻是 6 年，不是「一生只講一次」。像「有了孩子」這種句子在 20 年的中年層
  平均還是會出現 2 次左右 —— 這是刻意的，真實人生本來就會反覆做同類的事。
- 保底事件在 `<5` 層仍會出現安靜年份（一次性事件用完），因為幼兒期本來就沒什麼
  可以講的。要消掉得放寬年齡層切點，暫時不動。
- 新增事件沿用既有的 inline `en`／`zh`，所以非中英文語言看到的是繁中原文。
  這是這個函式一直以來的行為（`LANG === 'en' ? en : zh`），不是這次引入的；
  真要補齊得把這批事件搬進 `data/i18n.json`，是另一件獨立的工。
