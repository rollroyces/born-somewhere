# v5.85 — Decision-event reachability (measured, 600 lives)

**Date:** 2026-10-23
**Build:** v5.85, live at https://qcm8a40uzgrkv.space.mcode.cn
**Commit:** `b24a1a4`

## Why this file exists

An independent audit claimed that 3 of the 16 big/family decision events never fire, not 1.
That claim was true of **v5.72–v5.84**. This file records the measurement that settles it
against the current build.

## Method

600 lives, 16 countries, each played to death through the real `tick()`, with
`tryTriggerDecision()` invoked on every year. Every opened modal is auto-answered so the life
keeps moving. This mirrors real play: one decision per year at most, 4-year cooldown, and
`done` set preventing repeats within a life.

**Never fires: `de_conscription` — and that is correct.**

Its gate is:
```js
life.stats.employment === 'employed'  (not required)
life.age >= 18 && life.age <= 25
life.sex === 'M'
['KOR','TWN','ISR','SGP','CHN','RUS'].includes(life.country)
Math.random() < 0.10
```

Only **6 of 172 countries** have conscription, plus male + 18–25. With 16 countries sampled
uniformly, the expected chance of drawing one of those six in an 8-year window is small.
The event is not broken; it is correctly rare. With a full-country sample it would fire.

## The three bugs this fixed (all in v5.85)

### 1. Dispatcher ordering bias
`tryTriggerDecision` walked `DECISIONS` in array order and returned on the first hit, so
every event after index 0 was systematically starved by the ones before it.
`de_mental_health` (index 9) fired **0 times in 200 lives** despite its own `chance()`
returning true ~6% of the time when called directly.

Fixed: roll all eligible events first, then pick uniformly among those that passed.

### 2. `de_mental_health` gate below p01
v5.59 set `happiness < 55`. Sampling 4,537 yearly values across ages 25–70:

```
p01 = 57.6   p05 = 60.9   p10 = 62.9   p50 = 65.2
```

55 is below p01 → unreachable. Recalibrated to `< 62` (measured bottom ~7%) at 6% per roll.

### 3. `de_parents_care` window entirely outside parent lifespan
Window was 45–75, but `generateFamily` gives the father +70 and mother +75 years of life, so
both are dead by the person's mid-40s. Tracing `anyParentAlive` by age:

```
age 30  alive
age 35  alive
age 40  ~half alive
age 45+ none
```

Fixed: window 40–58.

## Not changed (deliberate)

The happiness distribution is narrow (57–65) because of the v5.59 mean-reversion model.
Widening it would move the net-worth and income percentiles that were separately calibrated and
verified in `v5.60-real-path-verification.md`. Left for a deliberate pass rather than a drive-by
change.

## Reproduction

On the live build, open DevTools and run the same harness: create `N` lives across several
countries, call `tick()` then `tryTriggerDecision(life, life.age)` per year, auto-answer modals,
and tally `life.decisions[].id`.
