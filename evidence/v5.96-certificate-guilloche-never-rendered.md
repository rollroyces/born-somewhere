# v5.96 — 死亡證書的底紋從來沒有畫出來過

## 量到的缺陷

訃聞畫面（`#view-end`）最上方的證書有一層 guilloche 底紋（同心橢圓 +
「8 億 分 之 1」浮水印）。在線上實測，它是**一片空白**：

```js
const cv = document.getElementById('certCanvas');
cv.getContext('2d').getImageData(0,0,cv.width,cv.height)
// → alpha 全為 0，取樣 0 筆非空像素
cv.width  // 300
cv.height // 150   ← <canvas> 的預設值，從來沒有被設定過
```

## 根因：把 SVG 塞進 canvas

`index.html` 裡是 `<canvas id="certCanvas"></canvas>`，但 `renderEnd()` 是這樣畫的：

```js
const cert = $('#certCanvas');
if (cert) cert.innerHTML = drawGuilloche(680, 420);   // 回傳的是 <svg> 字串
```

`<canvas>` **完全忽略自己的 innerHTML** —— 它只渲染 2D／WebGL context 畫上去的東西。
瀏覽器支援 canvas 時，innerHTML 裡的內容只當作「不支援 canvas 時的替代文字」，
既不顯示也不排版。

實測佐證：即使把 SVG 塞進去，DOM 裡確實有內容（8428 字元、67 個 ellipse、8 個 text），
但它的 `getBoundingClientRect()` 是 **0 × 0** —— 完全沒有版面。

所以這不是「畫錯」或「太淡」，而是這一層底紋**從第一版到現在從未被顯示過**。
跟 v5.71 的樹狀圖崩潰、v5.83 的家庭全景是同一類：看起來做了，實際上沒生效。

## 修法

把元素從 `<canvas>` 換成 `<div>`：

```html
<div id="certCanvas"></div>
```

安全性確認過三件事：

1. **CSS 與元素無關**：`#certCanvas { position: absolute; inset: 0; pointer-events: none; }`
   —— 不依賴 canvas 的顯示模型。
2. **PNG 匯出不走這條路**：`downloadLifeCertPNG()` / `downloadBirthCardPNG()`
   各自 `document.createElement('canvas')` 並用 `getContext('2d')`，
   並且自己重建一套 guilloche，完全不引用 `#certCanvas`。換元素不會影響下載的圖。
3. **全站沒有第二個同類錯誤**：掃過 `index.html` 的 `<canvas>` 與 `app.js` 的
   `getContext`，剩下的兩個 canvas 都是 JS 動態建立、也都正確使用 2D context。
   這是唯一一個「元素型別與用法不符」的地方。

## 修之後

```js
certCanvas.tagName  // "DIV"
svg                 // 存在
svg 尺寸             // 680 x 420  （原本 0 x 0）
ellipse 數          // 67
rendered            // true
```

截圖確認：證書上出現了放射狀的同心橢圓底紋與「8 億 分 之 1」浮水印，
`opacity: 0.08` 是原本的設計（低調壓在肖像後面），與設計值一致。

## 附帶確認

同一張截圖裡，`出生 2024/女` 也正確顯示 —— v5.94 那個修正在線上生效。

## 已知限制

- SVG 是固定 `680 × 420` 的絕對定位尺寸。`.end-cert` 是 `max-width: 720px; overflow: hidden`，
  所以桌機剛好放得下，但在較窄的視窗（< 680px）底紋會被裁掉右側。
  裁掉的是裝飾層、內容不受影響，且桌面為主的情況下看不出來。若之後要處理，
  正確做法是讓 SVG 用 `width="100%"` 搭配 `preserveAspectRatio`，而不是改數值。
- 這個元素沒有 `aria-hidden`，底紋是純裝飾。對螢幕閱讀器來說它沒有可讀文字
  （`<text>` 是裝飾水印），所以目前沒有實際影響，但補一個 `aria-hidden="true"`
  會更乾淨。
