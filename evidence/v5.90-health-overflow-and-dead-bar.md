# v5.90 — 健康值不再溢出到 108，也不再三十幾年不動

## 兩個一起修的缺陷

### 缺陷一：畫面上直接印出不可能的數字

58 條人生、每條都「永遠選第一個選項」跑到底：

```
32 歲  health=108   畫面數字「108」   長條 100%
46 歲  health=112   畫面數字「112」   長條 100%
```

**64% 的人生結束時 health > 100**（31/58），最高見到 **116.7**。

兩個原因疊在一起：

1. `newLife()` 給 `health: 100`，而一整批決策選項寫的是沒有夾的
   `life.stats.health += 8`（戒菸 +8、治療 +5、休假 +4、在家休息 +3、散步 +4…），
   同一個檔案裡其他統計量卻都寫了 `Math.min(100, …)`。
2. `renderLife()` 裡的 `set()` 只夾長條、數字直接印原值：

```js
valEl.textContent = Math.round(v);                              // ← 沒夾
barEl.style.width = Math.max(0, Math.min(100, v)) + '%';         // ← 有夾
```

所以玩家看到的是「健康條滿格，但旁邊寫 108」。

### 缺陷二：健康條前三十幾年是死的

同一組量測裡，健康的十年均值是：

```
0s 100 · 10s 100 · 20s 100 · 30s 101 · 40s 103 · 50s 104 · 60s 105
```

三十歲以前**每一年都精確是 100**。因為 `newLife` 給 100，而唯一的衰減是
`if (age > 60) health -= 0.3` —— 六十歲前完全不動，之後才每年掉 0.3。

這跟 v5.59 修掉的那四個死值是同一類問題：統計量存在，但對玩家沒有回饋。
而且因為起始值就已經在頂點，所有「+健康」的選擇都溢出，一點感覺不到。

## 修法

### 1. `bumpHealth()` — 所有寫入都夾在 0～100

12 處決策選項的 `apply()` 全部改走同一個 helper：

```js
function bumpHealth(life, delta) {
  if (!life || !life.stats) return;
  life.stats.health = Math.max(0, Math.min(100, life.stats.health + delta));
}
```

`set()` 的數字也一併夾，萬一以後有別的路徑寫入也不會再印出超界數字。

### 2. 健康改成跟著年齡走的曲線

```js
const ceil_ = Math.max(40, 100 - Math.max(0, age - 18) * 0.55);
hs.health += (ceil_ - hs.health) * 0.05;   // 每年往上限靠 5%
if (age > 60) hs.health -= 0.3;            // 保留原本 60 歲後的額外負擔
hs.health = Math.max(0, Math.min(100, hs.health));
```

身體每年回到「該年齡該有的樣子」5%，所以：

- 上限會隨年齡下降 → 條會動
- 選擇可以往上推，也可以往下壓，而且因為回歸只有 5%/年，一個好選擇可以撐好幾年

## 修之後

| 指標 | 修之前 | 修之後 |
|---|---|---|
| 結束時 health > 100 的人生 | **53%**（31/58） | **0%** |
| 單條人生 health 最高值 | 116.7 | 100.0 |
| 健康條前 30 年 | 每年精確 100 | 100 → 98（20s）→ 95（40s） |

一條 98 歲人生（心血管）實際走過的條：

```
12歲 100 · 24歲 99 · 36歲 96 · 48歲 91 · 60歲 86 · 72歲 77 · 84歲 69 · 96歲 62
```

畫面數字與長條一致，沒有再出現過 100 以上的值。

十年均值（58 條人生，10 個國家抽樣）：

| | 0s | 10s | 20s | 30s | 40s | 50s | 60s | 70s | 80s | 90s |
|---|---|---|---|---|---|---|---|---|---|---|
| 永遠選第一個 | 100 | 100 | 98 | 98 | 95 | 93 | 91 | 86 | 81 | 80 |
| 永遠選最後一個 | 100 | 100 | 98 | 97 | 94 | 90 | 88 | 82 | 78 | 75 |

兩種玩法從 30 歲後穩定拉開 3～5 分，健康選擇終於有意義。

## 連帶的數字變化（要誠實講出來）

`health` 會進幸福基準線 `baseline += (health − 60) × 0.35`。舊版溢出讓
「好選項」能白拿 108～116 的健康，等於多賺了 3～5 點幸福；現在這個假紅利沒了：

| | 修之前 | 修之後 |
|---|---|---|
| 幸福中位數（永遠選第一個） | 79.3 | **74.6** |
| 幸福中位數（永遠選最後一個） | 64.7 | **62.0** |
| 幸福落差 | 14.6 | 12.6 |

也就是說 v5.88 校準時量到的幸福分布**整體下移約 4.7 分**。這是修掉溢出後的正確值 ——
之前那 4.7 分本來就是 bug 送出來的紅利，不是設計。

## 為什麼可以安心改

動健康值之前先確認過耦合：

- `pDie()` 用的是 `lifeTable(c, sex)` 的生命表，**完全不讀 health** → 壽命分布不變
  （實測 USA 那條人生仍然 98 歲死於心血管）
- 全檔案沒有任何 `if (health < …)` 之類的判斷 → 沒有任何事件的觸發條件依賴它
- health 只有兩個消費者：幸福基準線、狀態條顯示

所以這次改動不可能偷偷改變死亡年齡分布，也不需要重跑 v5.88 的經濟校準。

## 順帶修正

「狀態代表什麼？」面板裡健康那一行原本寫著
`100 − 年齡 × 0.5（最大 0、最小 100）。60 歲後下降加速。`，
和新的曲線已經不符，改成描述實際模型。

## 順帶**沒有**做的事

一開始看到 172 國的 `social` 十年均值（60 → 61 → 65 → … → 79）幾乎只跟年齡走，
以為是 v5.59 那种死值。**實測後撤回這個判斷**：`social` 的選擇落差是 12 分
（永遠選第一個 77、最後一個 65），完全健康。當初那張表之所以平，是因為它平均了
兩種不同策略的人生。沒有動 `social`。

## 驗證方式

```js
// 58 個國家抽樣，每條都跑到自然死亡
startLife(cc);
for (k = 0; k < 130 && !life.died; k++) {
  STATE.paused = false; tick();
  tryTriggerDecision(life, life.age);
  // 永遠點 .dec-c 的第一個（或最後一個）→ 兩種策略
}
```

比對 `life.stats.health` 的最大值、是否 > 100、十年均值，以及幸福中位數。

### 已知限制

- 健康條在 0～18 歲仍然是 100（幼年本來就沒有明顯健康波動），所以前十幾年
  養生類選擇看不太出差別；差異從 20 歲後才累積出來。
- 5%/年 的回歸是拍的，不是校準出來的。如果之後發現「散步 +4」還是留不到一年，
  該調低回歸率而不是把 +4 加大。
- `bumpHealth` 只保護 health。若之後新增統計量，記得一樣走夾值 helper ——
  `knowledge`／`happiness`／`social` 目前各自在自己的 apply() 裡夾，沒有共用 helper。
