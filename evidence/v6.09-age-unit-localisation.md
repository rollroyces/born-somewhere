# v6.09 — 年齡單位「歲」寫死了，其他八種語言看到的是中文

## 量到的缺陷

用**韓語**跑一段人生，因為韓文與中文沒有共用字，任何漢字都可以直接判定是中文洩漏。
掃描人生畫面與訃聞畫面，得到上百筆中文：

```
life: 平均寿命 / 性別 / 学歴 / 仕事 / 配偶者 / 子供 / 同年生存率 / 出生地 / 城市
      手足 / 祖父母 / 純資産（PPP） / 主題 / 如果你現在出生 / 你的隨機出生地
end : 死亡原因分析 / 其他 / 事故 / 自殺 / 癌症 / 感染性疾病 / 再看一次 / 回到那一生
```

逐項追下去後，發現最大宗、最該先修的是**年齡單位**。

在 `renderLifeEventsFeed()`：

```js
<span class="lef-age">${e.age ?? '?'} ${isEn?'yo':'歲'}</span>
```

**英文以外一律是「歲」。** 而 `unit.years` 這個 key 九種語言早就都翻好了
（`歲 / yrs / 세 / 歳 / ans / ปี`）。

實測切換語言時盯著 `.lef-age` 這一格：

```
設 en   → LANG=en  → t('unit.years')='yrs' → 畫面「23 yo」
設 ko   → LANG=ko  → t('unit.years')='세'  → 畫面「23 歲」   ← 中文
設 zh   → LANG=zh  → t('unit.years')='歲'  → 畫面「23 歲」
設 ja   → LANG=ja  → t('unit.years')='歳'  → 畫面「23 歲」   ← 又是中文
```

`ko` 和 `ja` 拿到的是**繁體中文的「歲」**。這是最容易被看見的一處：
事件 feed 每一行都有一個年齡，是整個遊戲裡重複次數最多的字。

## 修法

把全部 **22 個**硬編碼的年齡單位換成既有的 `t('unit.years')`，
涵蓋五種寫法（有／無前導空格、`yo`／`yrs`、`isEn`／`LANG==='en'`）：

```js
(isEn?'yo':'歲')        →  t('unit.years')
(isEn ? 'yrs' : '歲')   →  t('unit.years')
(isEn?' yrs':'歲')      →  t('unit.years')
(LANG==='en'?'yrs':'歲') →  t('unit.years')
```

涵蓋的位置：事件 feed、最後時刻回顧、相較於隨機出生地的對照、
人生地圖說明、身分紀錄與家長年齡、同伴卡片、書架紀錄列、
書架地圖 tooltip、追思館、大家分享的人生、訃聞紀錄詳情、
反思題清單，以及匯出的出生卡與生命證書 SVG。

## 修之後（事件 feed 的年齡欄）

| 語言 | 修之前 | 修之後 | `t('unit.years')` |
|---|---|---|---|
| en | 20 yo | 20 **yrs** | yrs |
| ko | 20 **歲** | 20 **세** | 세 |
| ja | 20 **歲** | 20 **歳** | 歳 |
| fr | 20 **歲** | 20 **ans** | ans |
| th | 20 **歲** | 20 **ปี** | ปี |
| zh-Hant | 20 歲 | 20 歲 | 歲 |

全部與 `unit.years` 一致。檔案裡 `t('unit.years')` 的呼叫點從 11 個增加到 33 個，
硬編碼的年齡單位剩下 **0** 個。

## 這個修法為什麼只做這一小塊

掃描整個檔案的 `isEn ? '...' : '...'` 三元運算式：

```
總數            193
其中迴退值含漢字 192
```

**幾乎每一個都是英文或繁體中文的二選一。** 也就是說這個專案對九種語言的支援，
在「動態產生的內容」上基本上是裝飾性的 —— 韓語玩家看到的是一款中文遊戲。

這不是一個 bug 修得掉的，是**內容工程**：

- 約 190 條字串 × 另外 7 種語言 ≈ 1,300 筆翻譯
- 加上 `generateYearlyEvent()` 整個年齡層事件池（v5.89 剛擴充到 40 組）也是中英雙語
- 加上決策選項的 label / sub / log（那些已經在 i18n 裡，是好的）

硬把這 190 條塞進 `data/i18n.json` 是一次大改動、而且需要真的翻譯，
不是可以順手做掉的事。所以這次只挑**重複次數最高、風險最低、既有翻譯已經現成**的那一塊
（年齡單位）先修，剩下的如實記錄下來。

## 已知的其餘缺口（依影響排序）

1. **年齡層事件池**（`generateYearlyEvent`）：每段人生 70～80 條旁白，中英雙語。
   這是玩家閱讀量最大的文字，但也是最大的翻譯工作量。
2. **狀態說明面板**：`si-row` 四行中英雙語（v5.95 剛把內容改對，但沒接 i18n）。
3. **國家統計面板**：20 個欄位的名稱與單位，中英雙語。
4. **約 190 條零散字串**：按鈕、說明文字、toast、家族關係稱謂。

## 一個可以馬上做、成本極低的補強

`t()` 在找不到 key 時**原樣回傳 key 字串**，不報錯也不留 console 線索。
這正是 v6.08 讓我一度以為「稽核全過、實際卻是壞的」的原因。

改成缺值時 `console.warn` 一行，之後所有「key 沒接上／沒定義」的問題
都會自己浮出來，不需要再靠人工比對資料檔與程式碼。

這是一行改動，但屬於全域行為變更，該不該在沒有共識的情況下動，
我留給你決定。

## 建議保留的檢查

這輪找到的三個資料層缺陷（v6.06 自殺率、v6.07 宗教、v6.09 年齡單位）
全部來自同一個作法：

1. **把 `countries.json` 的欄位逐一對照 `app.js` 的引用** → 抓到 `sf`、`rel`
2. **把 `i18n.json` 的 key 逐一對照引用** → 抓到 `intro.bc.*`
3. **用與目標文字無關的語言（韓文）掃描畫面上的漢字** → 抓到年齡單位與整體缺口

三個都是幾秒到幾十秒的成本，抓到的都是量級不小、而且**外觀完全正常**的錯誤。
