# v6.05 — 「合併 6 段人生」下面只有一個人

## 量到的缺陷

書架上有 6 段人生，按「🌐 家族全景圖」，視窗裡寫著：

```
🌐 家族全景圖
合併多段人生的族譜
無共同親屬
🇦🇲Richardson Ronald2024 – 2100†        ← 只有這一個人
```

**只畫出一個人。** 玩家很自然會以為合併失敗了。

## 根因：樹固定以「第一段人生」為根，而第一段常常是孤兒

```js
renderMiniTree($('#lifeTree'), selfNodes[0].id, 2, allPeople, allEdges);
```

`selfNodes[0]` 就是 `lives[0]`。而 `generateFamily()` 會依該國的孤兒率決定要不要給父母
—— **20 條人生實測約 5% 沒有父母**。那一段當根時，`edges.filter(e => e.childId === id)`
回傳空陣列，整張樹就只剩自己一個節點。

實測重現：4 段人生裡第一段（Rogers Naomi）的 family 是

```js
{ parents: 0, siblings: 0, grandparents: 0 }   // 其他三段都有父母
```

於是樹只有 1 個節點。

## 確認「共同親屬」功能本身是好的

先用合成資料單獨測 `findCommonAncestors()`：兩個人共用一位父親 → 正確回傳
`{name:'共同的父親', count:2}`。所以「找出多段人生的共同親屬」是真的有在做事，
壞掉的只有底下那張樹的取根方式。

## 修法

### 1. 挑「往上最多代」的那一段當根

```js
const ancestorCount = (id) => allEdges.filter(e => e.childId === id).length;
let rootSelf = selfNodes[0];
let best = ancestorCount(rootSelf.id);
for (const s of selfNodes) {
  const c = ancestorCount(s.id);
  if (c > best) { best = c; rootSelf = s; }
}
```

有親屬的才畫得出東西；真的全部都沒有親屬時，仍會落到 `selfNodes[0]`，行為不變。

### 2. 誠實標示這張樹的範圍

原本只寫「合併多段人生的族譜」，底下卻只畫一段人生。加一行說明：

```
合併多段人生的族譜
無共同親屬
下方的樹以 Richardson Ronald 為中心，往上兩代。   ← 新增
```

`renderMiniTree` 的 `maxGen` 本來就固定傳 2，所以「往上兩代」是實際行為的描述，
不是修飾詞。

## 修之後（6 段人生）

```
pano.rootLine : 下方的樹以 Richardson Ronald 為中心，往上兩代。
pano.treeNodes: 4
pano.names    : Richardson Ronald / Cook Gerald / Cooper Paisley / Hill Hannah
```

同一組資料修之前是 1 個節點。

| | 修之前 | 修之後 |
|---|---|---|
| 樹的節點數 | **1**（剛好抽到孤兒那段） | **4** |
| 有無說明範圍 | 無 | 有，標示以誰為中心 |

## 修這段時我自己犯的錯（兩次）

第一次補上「以誰為中心」那行時，我用 `<div id="lifeTree">` 當錨點，
但這個字串在檔案裡出現兩次 —— `showLifeModal()` 和 `renderPanorama()` 各一次。
`replace(..., 1)` 命中的是**前者**，結果在 `showLifeModal` 裡留下一段
引用 `rootSelf` 的程式碼，而那個函式沒有 `rootSelf` → 一開詳情視窗就會
`ReferenceError`。

第二次我改成「找第一個 lifeTree」，還是同一個錯誤（第一個仍然是 `showLifeModal` 的）。
最後改成**以 `let rootSelf = selfNodes[0];` 這行為錨點往後找**才對。

驗證時發現 `.panorama-root` 查不到，才暴露這個問題 ——
如果只測全景圖不看詳情視窗，這個錯誤會直接上線。

## 修完後兩個視窗都驗過

| | 全景圖 | 書架詳情視窗 |
|---|---|---|
| 標題 | ✅ | ✅ `🇦🇲 Richardson Ronald` |
| 節點數 | 4 | 4 |
| 有「以誰為中心」那行 | ✅ | ❌（正確，不应该有） |
| 未捕捉錯誤 | 0 | 0 |

## 已知限制（**沒有**解決）

樹仍然只畫**一段人生**、往上兩代，不是真正的「合併 N 段人生」。
上面那行說明只是把限制講清楚，沒有把功能補滿。

要做到真的合併， 需要一個能同時放多個根的森林式排版（現在 `renderMiniTree`
的 xSlot 是用 `2^(maxGen-gen-1)` 算的，只支援單一根）。那是版面演算法的工作，
不是小修，而且「50 段人生要怎麼塞進一張圖」本身是產品決策 ——
所以這次先修「看起來壞掉」的部分。

共同親屬清單（`findCommonAncestors`）本來就橫跨全部人生，那部分一直是對的。
