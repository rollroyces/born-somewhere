# v6.03 — 書架的「檢視」把名字印成 `[object Object]`

## 量到的缺陷

在書架按「📋 整理紀錄」→「檢視」，跳出來的詳情視窗是：

```
× 🇬🇷 [object Object]  2024 → 2114 · 90 歲 · 呼吸系統
🇬🇷[object Object]2024 – 2114†
🇬🇷Diaz Rui1994 – 2064†
🇬🇷Nelson Violet1992 – 2069†
...
```

標題和家族樹裡的「自己」都是 `[object Object]`。

## 根因：`life.name` 是物件，卻被當字串用

兩種形狀的 `name` 會流到同一段顯示程式碼：

| 來源 | `name` 的型別 | 值 |
|---|---|---|
| 書架摘要殼（`rec.name`） | **字串** | `"Cruz Caroline"` |
| 完整人生（`rec.full.name`） | **物件** | `{last:"Cruz", first:"Caroline", full:"Cruz Caroline", full_en:…}` |

`showLifeModal()` 第一行就是 `const life = rec.full || rec;`（v5.83 為拿得到
family/quotes 才改成優先用 `.full`），所以它拿到的一定是**物件**那一種。
而舊碼是：

```js
<h2 class="lm-title">${c?.flag || ''} ${escapeHtml(life.name)}</h2>   // ← 直接當字串
...
const self = { id: 'self_life', name: life.name, ... };                // ← 同樣
```

`escapeHtml()` 最終會 `String(物件)`，於是變成 `[object Object]`。

這個檔案裡其他 8 處都寫成 `name?.full || name?.full_en`，所以訃聞、
分享圖、匯出、地圖全都正常 —— 只有這一個視窗漏了。

## 修法：集中成一個函式

```js
function displayNameOf(x, fallback = '') {
  if (!x) return fallback;
  if (typeof x === 'string') return x;      // 摘要殼：字串
  return x.full || x.full_en || fallback;   // 完整人生：物件
}
```

兩處改成：

```js
${escapeHtml(displayNameOf(life.name, rec.name || '—'))}   // 標題
name: displayNameOf(life.name, ''),                        // 家族樹的自己
```

### 為什麼叫 `displayNameOf` 而不是 `lifeName`

原本要叫 `lifeName`，但 `findSelfInGedcom()` 裡已經有一個
`const lifeName = STATE.life.name.full || ...`，會把新的全域函式遮蔽掉。
雖然兩者暫時不會互相呼叫（遮蔽的那個函式不會用到新函式），但留下這種
同名遮蔽是個陷阱，改名避開。

### 修法過程中我自己犯的錯

第二個補丁（家族樹那行）套錯位置了：`name: displayNameOf(life.name, rec.name || '')`
被套進了 `renderLifeTreeInto(life, container)`，那個函式**沒有** `rec` 參數，
一執行就 `ReferenceError: rec is not defined`。是跑驗證時的
`Uncaught ReferenceError` 抓到的，改成傳空字串才對。

## 修之後

| | 修之前 | 修之後 |
|---|---|---|
| 視窗標題 | `🇬🇷 [object Object]` | `🇬🇷 Cruz Caroline` ✅ |
| 家族樹的自己 | `🇬🇷[object Object]2024 – 2114†` | `🇬🇷Cruz Caroline2024 – 2114†` ✅ |
| 整個視窗是否還含 `[object Object]` | 是 | **否** ✅ |
| 未捕捉錯誤 | 0（但輸出錯誤） | 0 ✅ |

## 已知限制

- 其餘 7 處 `name?.full || name?.full_en` 沒有改成呼叫 `displayNameOf()`。
  它們目前是正確的，重構屬於整理性質、沒有修到任何東西，這次不動
  （v6.02、v6.03 都採「只修實際壞掉的地方」的原則）。
- 這代表同一個概念在檔案裡仍以兩種寫法存在。等之後真的需要統一時，
  `displayNameOf()` 已經在那裡可以直接取代。
