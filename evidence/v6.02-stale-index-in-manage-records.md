# v6.02 — 整理紀錄視窗裡的「檢視」會無聲無息地失敗

## 怎麼找到的

延伸 v6.01 的按鈕掃描：這次連破壞性按鈕也按（把 `confirm` stub 成一律回 true，
並把 `<a>.click()` 與 `URL.createObjectURL` 暫時攔下，避免真的跳轉或下載）。
掃 58 顆按鈕，得到：

```
Uncaught TypeError: Cannot read properties of undefined (reading 'full') @4493
```

## 根因：按鈕的索引是渲染當下定下的，清單卻是點擊當下才重讀的

`showManageRecordsModal()`：

```js
// 渲染時：按鈕的 data-i 是「當下第幾筆」
<button data-i="${i}" data-act="show">

// 點擊時：ls 是「現在」的清單
const idx = +btn.dataset.i;
const ls = loadPastLives();
if (act === 'show') showLifeModal(ls[idx]);   // ← idx 可能已經不存在
```

只要兩者之間紀錄數量變了 —— 另一個分頁刪掉、訃聞畫面按了「刪除所有」、
或任何外部寫入 —— `idx` 就會指向清單尾端之外，`ls[idx]` 是 `undefined`，
`showLifeModal(undefined)` 立刻拋 `TypeError`。

而 `showLifeModal()` 的第一件事就是 `const life = rec.full || rec;`，
所以錯誤訊息是「讀取 undefined 的 'full'」。

## 確定性重現

```
渲染時紀錄數：4      按鈕 data-i：[0, 1, 2, 3]
點擊前紀錄數：2      （在視窗開著的情況下把清單砍掉後兩筆）
點 data-i="3"  →  Uncaught TypeError @4493
                →  lifeModal 沒有開啟，畫面毫無反應
```

同一個 `ls[idx]` 也用在 `del` 分支，那邊只是 `splice` 超出範圍的無害 no-op，
所以只有「檢視」是明顯壞掉。

## 修法

改用紀錄唯一的 `ts` 找回它在現存清單裡的位置，而不是信任凍結的索引：

```js
const target = livesSnapshot[renderIdx];          // 渲染當下的快照
let idx = target ? ls.findIndex(r => r.ts === target.ts) : -1;
if (!target || idx < 0) {
  modal.remove();
  renderShelf();
  toast(isEn ? 'This record has already been deleted' : '這段紀錄已經被刪除了');
  return;
}
```

順帶修掉 `del` 分支同樣的索引失效問題 —— 它現在也會刪到正確的那一筆，
而不是誤刪當下第 idx 筆。

## 修之後（4 → 2 的同一個重現步驟）

| | 修之前 | 修之後 |
|---|---|---|
| 按已失效的索引 | TypeError，**完全沒反應** | toast「這段紀錄已經被刪除了」，視窗自動關閉 ✅ |
| 未捕捉錯誤 | 1 個 | **0 個** |
| 按仍然有效的索引 | 正常開啟詳情 | 正常開啟詳情 ✅ |
