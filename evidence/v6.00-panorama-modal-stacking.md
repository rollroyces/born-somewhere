# v6.00 — 全景圖按第二次，× 鈕就再也關不掉了

## 量到的缺陷

在書架（50 段人生）按「🌐 家族全景圖」兩次，然後把兩個視窗分別標記成
`BOTTOM` / `TOP`，再按**眼前看得到的那個**（TOP）的 × 鈕：

```
按下之前： ['BOTTOM', 'TOP']
使用者按 × 的對象：TOP
按下之後： ['TOP']
```

**被移除的是 BOTTOM（藏在底下那個），TOP 還在畫面上。**

也就是：按了 × 之後，畫面看起來完全沒反應。

## 兩個原因疊在一起

### 一、`renderPanorama` 沒有先移除舊視窗

```js
const modal = document.createElement('div');
modal.id = 'lifeModal';
...
document.body.appendChild(modal);      // ← 從來不先清掉既有的
```

同一個檔案裡的 `showLifeModal()` **本來就有**這一行：

```js
document.querySelector('#lifeModal')?.remove();   // v5.83 加的
```

`renderPanorama()` 是漏掉的。實測按 1 次 → 1 個視窗、按 2 次 → 2 個、按 3 次 → 3 個，
每個都 `z-index: 100`、`top: 0`，完全疊在一起。

### 二、× 鈕移除的是「文件順序裡第一個」而不是「自己」

```js
<button class="lm-close" onclick="document.getElementById('lifeModal').remove()">×</button>
```

`getElementById()` 回傳的是文件中**第一個**符合的 id，也就是最早 append 的那個 ——
被压在最底下、玩家根本看不到的那個。

只要畫面上曾經同時存在兩個 `#lifeModal`，這個 × 就一定按錯目標。
第一個原因讓重複很容易發生，第二個原因讓關閉一定失敗。

## 修法

1. `renderPanorama()` 開頭加上與 `showLifeModal()` 一致的清理行。
2. 兩處 lifeModal 的 × 都改成**移除自己**，不再依賴 `getElementById` 的文件順序：

```js
document.body.appendChild(modal);
// v6.00：× 移除「自己」這個 modal，不依賴 getElementById 的文件順序
modal.querySelector('.lm-close')?.addEventListener('click', () => modal.remove());
```

按鈕本身也從 inline `onclick` 改成 `<button class="lm-close" type="button">`，
行為交給上面這個綁定 —— 順帶補上了原本沒有的 `type="button"`
（放在 form 裡會預設成 submit）。

## 修之後（50 段人生）

| | 修之前 | 修之後 |
|---|---|---|
| 按第 1 次 | 1 個視窗 | 1 個 |
| 按第 2 次 | **2 個** | **1 個** |
| 按第 3 次 | **3 個** | **1 個** |
| 按 × 之後剩下 | **1 個（關不掉）** | **0 個** |

## 順帶修掉稽核腳本自己的一個脆弱點

升到 v6.00 時 `i18n_audit.py` 報 TOTAL: 3 —— v5.98 新增的版本一致性檢查，
正則寫死了 `v(5\.\d+)`，跨不過 5.x → 6.00。改成 `\d+\.\d+` 之後恢復正常，
負向測試照舊（有漂移 exit 1、乾淨 exit 0）。

## 已知限制

- 全景圖的樹只畫 `renderMiniTree(lifeTree, selfNodes[0].id, 2, ...)` ——
  以第一段人生為中心、深度 2。50 段隨機人生通常沒有共同親屬，
  實測只會出現 2 個節點。這是「合併找出共同祖先」這個設計本身的結果，
  不是缺陷；但畫面在多數情況下會相當空，看起來像沒做完。
  要讓它有內容就得放寬深度或改成「隨機挑一個 self」，那是產品決策。
- `manageModal` / `shortcutsModal` / `feedbackModal` / `changelogModal`
  的 × 仍是 inline `onclick="document.getElementById('xxx').remove()"`。
  這些都是單例視窗（不會重複建立），所以目前不會犯同樣的錯；
  這次只修了實際會出問題的 lifeModal 那一組。
