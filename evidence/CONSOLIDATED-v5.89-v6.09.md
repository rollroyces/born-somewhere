## 二、六種缺陷型態

### A. 資料存在、程式碼從未讀取（v6.06、v6.07）

最隱蔽的一類。函式完整、邏輯通順、資料格式乾淨，但**欄位沒有被接上**。

```
$ grep -n "\.sf\b" app.js   →  NONE
$ grep -n "\.rel\b" app.js  →  NONE
```

`countries.json` 172 國的 `sf`（自殺率）與 `rel`（宗教分布）都從未被讀取。
v6.07 還多一層：`region` 欄位是**混用的軸**（134 國放地理區、38 國放收入級距 `'hi'`），
依賴它的宗教表沒有 `hi` 這個 key，於是美國、日本、德國、以色列、台灣、韓國
的宗教被記成 100%「無信仰」。

### B. 程式寫了、資料也存了，但輸出玩家看不到（v5.96、v6.04）

```
v5.96  cert.innerHTML = drawGuilloche(...)   // <canvas> 完全忽略自己的 innerHTML
v6.04  life.decisions.push({... note: noteText})  // 全檔案沒有任何地方讀 r.note
```

兩者的共同點是**外觀完全正常** —— 畫面上少了一層底紋、少了一行字，
不仔細看會以為是設計如此。

### C. 單位 / 座標系錯誤（v5.97）

`c.pop` 的單位是「千人」（172 國加總 8,078,638 → 80.8 億人），
顯示時卻除以 1,000,000。台灣顯示「0.0 百萬人」。

### D. 索引與狀態不同步（v5.92、v6.02）

按鈕的索引在**渲染當下**定下，清單卻在**點擊當下**重讀。
中間只要數量變了，索引就指向不存在的位置。

### E. 版本漂移（v5.98）

五份各自硬編碼的版本字串全部不一致，而且沒有任何機制保證它們同步。
最外顯的是玩家會**分享出去的**圖片上印著 v5.12 與 v5.2。

### F. 在地化只做了介面殼（v6.08、v6.09）

`i18n.json` 裡有完整翻譯、程式碼卻沒接；或是字串直接寫死中英二選一。

## 三、怎麼找到它們的

這三個檢查成本都很低，抓到的都是量級不小、而且外觀正常的錯誤：

| 檢查 | 做法 | 抓到 |
|---|---|---|
| **欄位對照** | 把 `countries.json` 每個欄位逐一對照 `app.js` 的引用 | v6.06 `sf`、v6.07 `rel` |
| **key 對照** | 把 `i18n.json` 每個 key 逐一對照引用 | v6.08 `intro.bc.*` |
| **異語言掃描** | 用與目標文字**無共用字**的語言（韓文）掃畫面上的漢字 | v6.09 年齡單位、整體在地化缺口 |
| **按鈕全掃描** | 每個畫面每顆按鈕都按，掛 `window.onerror` | v6.01 `isEn`、v6.02 失效索引、v6.00 疊視窗 |

按鈕全掃描一次挖出三個從沒有人回報過的缺陷 —— 它們的共同點是
**只有在按下去那一刻才會拋**，讀程式碼幾乎不可能注意到。

## 四、量測方法與踩過的坑

這份報告裡的每個數字都是量出來的。以下幾點是過程中真的絆倒過的：

| 陷阱 | 後果 |
|---|---|
| 清 SW 與 cache 後**只重載一次** | 頁面可能在新 SW 預存完成前就把 i18n 讀進記憶體（v6.08 踩到） |
| 視窗只有 500px 寬就下結論「按鈕壞了」 | 那是 `@media (max-width:520px)` 刻意收起次要控制鈕 |
| 只抽幾十條人生比較死因比例 | 自殺是低頻死因，差異會淹在雜訊裡（v6.06 踩到） |
| 用 `c.sf \|\| 10` 處理 0 值 | `sf=0` 是 falsy → 那 5 國反而拿到中位數權重（v6.06 踩到） |
| 補丁錨點用 `<div id="lifeTree">` | 該字串在檔案裡出現兩次，`replace(...,1)` 命中錯的那個（v6.05 踩到，連錯兩次） |
| `suspect` 顯示異常時就宣稱是 bug | 追思館空白狀態其實正常，是我的測試環境留下髒狀態（v6.05 踩到） |

## 五、尚未解決的缺口

### 1. 九語言支援在動態內容上基本是裝飾性的

```
app.js 裡 isEn ? ... : ... 三元運算式：193 個，其中迴退值含漢字 192 個
```

韓語玩家看到的人生畫面與訃聞畫面，幾乎整片是繁體中文。
這是**內容工程**（約 190 條 × 7 種語言 ≈ 1,300 筆翻譯），不是 bug 修得掉的。
v6.08 / v6.09 只挑了「既有翻譯已現成」的部分先修。

### 2. 更新說明內容停在 v5.19

`CHANGELOG` 陣列與 `CHANGELOG.md` 都只到 v5.19，
v5.20 → v6.09 這段（包含本報告的 21 個修正）玩家在遊戲裡看不到。
已在本輪一併合併更新。

### 3. 全景圖只畫一段人生

v6.05 讓它不再只畫一個節點，但仍是「以一段人生為中心、往上兩代」，
不是真正的多根森林。要補滿需要新的排版演算法 + 「50 段人生怎麼塞進一張圖」的產品決策。

### 4. 切換語言不會重譯已產生的旁白

`life.log` 存的是**生成當下**的已翻譯字串，之後切換語言，舊事件維持原語言。
要修得把 log 改成存 key + 參數，是資料模型改動。

### 5. 沒有 lint

v6.01 的 `isEn` 是「未宣告識別字」，正是 ESLint 的 `no-undef` 最擅長抓的類型。
這個專案沒有 `package.json`、沒有 lint 設定。

## 六、建議保留的兩個一行改動

- `t()` 找不到 key 時**原樣回傳、不報錯** —— 改成 `console.warn`，
  這類「key 沒接上／沒定義」的問題就會自己浮出來，不需要再靠人工比對資料檔與程式碼。
- 把「欄位對照」「key 對照」「異語言掃描」「按鈕全掃描」四個檢查寫成腳本，
  成本都是幾秒到幾十秒。
