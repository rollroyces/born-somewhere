# v5.58 — Global `[hidden]` Fix

**Date:** 2026-10-22
**Commit:** (see git log)
**Live:** https://qcm8a40uzgrkv.space.mcode.cn

## Defect

`born-somewhere/styles.css` had no global `[hidden] { display: none }` reset. Only four
component-specific guards existed:

```css
.modal[hidden]      { display: none; }
.toast[hidden]      { display: none; }
.app-footer[hidden] { display: none; }
.edu-badge[hidden]  { display: none; }
```

Any element that carries an explicit `display` in CSS therefore **ignores** the `hidden`
attribute, because a class selector beats the user-agent stylesheet's
`[hidden] { display: none }`.

Two affected elements were found:

| Element | CSS | Symptom |
|---|---|---|
| `.dec-note-wrap` (added v5.55) | `display: flex` | The "leave a note" textarea rendered on **every** decision modal, including the ones that don't accept a note. Text typed there was silently discarded. |
| `.cert-controls` (pre-existing) | `display: flex` | The retired pause/speed shell was laid out instead of hidden. Children carry their own `hidden`, so it collapsed to zero height and was not visibly broken — but it was not actually hidden either. |

## Fix

Copied the original's reset verbatim — `1in8b.life/zh/` ships
`[hidden]{display:none!important}` in its inline `<style>` block:

```css
[hidden] { display: none !important; }
```

placed at the very top of `styles.css`, before `:root`.

No regressions: every modal still appears when its `hidden` attribute is removed, and the
pause/resume path through `closeModal()` still clears `STATE.paused`.
