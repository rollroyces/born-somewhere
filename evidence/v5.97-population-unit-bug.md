# v5.97 — 172 個國家的人口全部小了一千倍

## 量到的缺陷

展開人生裡的「🌍 國家關鍵統計」面板，台灣那一行是：

```
人口 0.0 百萬人
```

台灣人口約 2331 萬，也就是 **23.3 百萬人**。少了一千倍。

## 根因：`c.pop` 的單位是「千人」，顯示時卻除以一百萬

決定性證據是把 172 國的 `c.pop` 加總：

```
sum(c.pop) = 8,078,638

若視為「千人」 → 8,078,638 × 1000 = 80.8 億   ← 世界人口，合理
若視為「人」   →                = 0.0081 億  ← 不可能
```

台灣 `pop = 23317`（千人）= 2331.7 萬人；印度 `pop = 1438070` = 14.38 億人；
中國 `1,422,585` = 14.23 億人。都對得上。

但顯示那行寫的是：

```js
((c.pop || 5000000) / 1000000).toFixed(1) + '百萬人'    // 舊碼
```

除以 1,000,000（百萬）而不是 1,000（千人）。所以：

| 國家 | 修之前顯示 | 實際 |
|---|---|---|
| 台灣 | 0.0 百萬人 | 23.3 百萬人 |
| 美國 | 0.3 百萬人 | 343.5 百萬人 |
| 日本 | 0.1 百萬人 | 124.4 百萬人 |
| 阿富汗 | 0.0 百萬人 | 41.5 百萬人 |
| 印度 | 1.4 百萬人 | **1.4 億人** |
| 中國 | 1.4 百萬人 | **14.2 億人** |

大多數國家四捨五入成「0.0 百萬人」；印度、中國則因為本來就大，
顯示出一個看起來「有數字但小得離譜」的值 —— 比顯示 0 更難讓人察覺是 bug。

順帶一提，預設值 `5000000` 也跟錯單位（千人欄位的預設應該是 5000），
雖然 172 國都有 `pop` 所以從未觸發，仍一併修正。

## 為什麼其他統計量都對

同一個面板裡順手核對了每一列的單位，確認只有 `pop` 出錯：

| 欄位 | 資料單位 | 換算 | 狀態 |
|---|---|---|---|
| `pop` | 千人 | ÷1000 | ❌ 原本 ÷1e6，已修 |
| `births` | 人／年 | 直接顯示 | ✅ |
| `u5` | 每千活產 | ÷1000×100 | ✅ 台灣 5.0 → 0.5%、阿富汗 54.9 → 5.5% |
| `le` | 歲 | 直接顯示 | ✅ |
| `ppp` | 美元 | 直接顯示 | ✅ |
| `urb` / `agr` / `net` / `ter` / `tfr` | % / 年 / 人 | 直接顯示 | ✅ |

## 沒有動的地方

`c.pop` 另外兩處使用（`countryProbabilities()` 的第 958、976 行）是當**權重**，
只需要彼此同尺度即可，千人與人的比例完全相同，所以那裡沒有錯、也不需要動。

## 已知限制

- 印度、中國以「百萬人」為單位會顯示四位數（1438.1、1422.6）。
  這在數學上正確但讀起來彆扭，較好的做法是超過 1000 百萬時改用「億」。
  目前維持一致的單位、不再新增特例；若要改，應該連同面板其他
  大數字（每年出生人數已是絕對值）一起重新考慮呈現方式。
- 這個欄位只在「國家關鍵統計」面板出現；intro 的國家資訊卡顯示的是
  地區／壽命／嬰兒死亡率／移民率／人均GDP，沒有顯示人口，所以不受影響。
